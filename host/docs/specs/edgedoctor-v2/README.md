# EdgeDoctor V2：板载振动监测与 MQTT 告警方案

日期：2026-09-09。状态：实现进行中；板端 IMU、基线、MQTT、telemetry、服务端趋势和通知适配已落地，现场长稳与手机显示仍是验收项。

## 已确定的范围

- 用户选择仅使用板载 IMU；先验收真实低频振动、基线和异常监测，现场五分类另行验证。
- 使用 MQTT；同时建设局域网 Broker、告警服务、网页看板和手机通知适配。
- 覆盖报警留证、未知/不确定状态、趋势与设备档案、诊断依据、XiaoZhi 查询与播报。
- 技术规格、测试规格、UI 规格和视觉原型保留为设计依据；当前实现以固件、服务端和自动化测试为准，原型仍使用合成数据。

## 推荐方案及取舍

选择“板端自主监测 + 事件驱动 MQTT + 局域网服务”。断网不影响本地报警；服务端负责持久化、通知、跨设备查询；板子是本地报警状态的权威来源。

对比：只接推送机器人开发快，但缺历史和确认；将推理放在云端增加网络依赖，对当前板载小模型没有必要；完整 IoT 平台增加部署负担。本方案默认 1 台设备，服务端按 10 台设备验收。

| 当前静态模型 2508 B，离线准确率 96.50% | 保留既有结果；不把这些数字当作现场 IMU 精度 |

## 范围与硬件门禁

默认目标为 208 Hz、三轴、±4 g、分析频带 5–40 Hz。这个配置是待上板验证的工程目标，不是已验证能力；ODR、FIFO、滤波寄存器以实机型号对应数据手册为准。

硬件发现若与 LSM6DS3 不符，停止写寄存器，记录 ID 与总线情况，更新适配器和验收 profile；不能直接套用地址/灵敏度。若 FIFO 无法无丢样运行，采集门禁失败，不能以低速轮询冒充达标。

本版本不承诺轴承高频故障诊断、标准化机械健康等级、剩余寿命或自动停机。不会把低频数据插值到 6.4 kHz 后交给旧模型。未建立匹配基线时，只显示物理量和质量状态。

## 交付阶段

1. M0：冻结基线、硬件/存储/资源确认、拆出报警核心。
2. M1：真实 IMU、质量与基线、本地告警及故障片段。
3. M2：MQTT、服务端、网页、应用回执、离线补传与手机通知。
4. M3：新 LVGL 页面、趋势、档案、解释与证据回放。
5. M4：语音工具、播报仲裁、故障注入和 8 小时整机验收。

推荐由一条集成主线顺序推进，每个功能变化后构建，保留官方 XiaoZhi 基线。完成这套 V2 的规划量级约为 15–25 个工程人日，另留硬件调试与运行验收时间；这是估算，M0 后按实测资源重估。
