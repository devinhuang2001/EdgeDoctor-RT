# EdgeDoctor-RT 项目展示与讲稿

## 一句话故事

EdgeDoctor-RT 把“采集振动—识别故障—本地解释—维护处置”压缩到一块运行 RT-Thread 的 PSoC™ Edge E84 MCU 上：不依赖云端即可完成五类状态诊断，并用可验证的量化与跨负载实验说明它既轻量，也诚实面对泛化边界。

## 推荐叙事主线

不要把项目讲成“训练了一个准确率很高的模型”，而要讲成一个完整闭环：

1. 工业现场停机代价高，云端诊断存在时延、网络和数据边界问题。
2. 因此把诊断放到设备侧，并让采集、推理、界面和日志在 RTOS 中持续协同。
3. 数据按原始记录分组切分，避免窗口泄漏；用 LOLO 检验未见负载。
4. 结构化频域特征把长波形压成 64 维稳定输入，64–32–5 MLP 适合 MCU。
5. 静态 INT8 仅 2,504 B，验证集 Accuracy 97.00%，与 FP32 预测一致率 99.50%。
6. 4 Nm 留出负载 Macro-F1 降到 77.88%，这不是掩盖项，而是下一阶段域泛化和校准的明确任务。
7. 最终价值不是一张分类结果，而是可持续运行、可解释、可留痕的本地维护闭环。

## 13 页逐页讲法（约 5–7 分钟）

### 1. 封面：20 秒

“我们做的是 EdgeDoctor-RT：面向旋转机械预测性维护的离线 Edge AI 与 RTOS 工业诊断终端。今天重点回答三个问题：为什么必须在现场做、怎么在 MCU 上做、证据是否可信。”

### 2. 问题：30 秒

从停机损失、本地闭环、五类状态三个信息切入。强调行业成本数据是背景量级，不把它说成项目实测收益。

### 3. 产品答案：25 秒

指出硬件、RT-Thread、离线推理和本地显示构成完整终端。不要宣称已在 Ethos-U55 上完成加速；当前推理后端是 Reference C。

### 4. 系统架构：30 秒

按“感知层—信号层—AI 层—交互层”从左上到右下讲，说明数据如何最终变成维护动作。

### 5. 数据可信度：35 秒

先说 45 条原始记录生成 1,800 个窗口，再强调按记录分组切分，防止相邻窗口同时进入训练与测试导致虚高。

### 6. 特征链：30 秒

用四步快速带过：25.6 kHz 降采样到 6.4 kHz；1 秒窗口、0.5 秒步长；64 个频带能量；输入 64–32–5 MLP。

### 7. 轻量模型：30 秒

三个数字必须解释清楚：2,504 B 是模型参数体积，不是完整固件；97.00% 是静态 INT8 Accuracy；99.50% 是 INT8 与 FP32 预测一致率。

### 8. 量化验证：30 秒

先读左侧柱状图：FP32 和 INT8 指标几乎不变；再读右侧三张卡，主动说明当前部署边界和后续 NPU 加速方向。

### 9. 跨负载泛化：40 秒

这是答辩可信度的关键页。2 Nm 留出最好为 90.44%，4 Nm 最难为 77.88%。结论是模型已有迁移能力，但仍需针对工况偏移做域泛化和置信度校准。

### 10. RTOS 产品化：35 秒

强调 Capture、Window+Infer、HMI+Log、Network 四类任务互不阻塞。AI 不是一次脚本调用，而是持续运行的系统组件。

### 11. 本地 HMI：25 秒

介绍 Overview、Signals、Diagnosis、System 四页如何把结果转化为“发现—解释—处置—留痕”的维护闭环。

### 12. 比赛演示：30 秒

按时间轴演示：前 60 秒看实时采集和页面；60–180 秒解释量化与 LOLO 证据；最后说明板端测时、功耗、U55 加速与更多工况验证计划。

### 13. 结尾：15 秒

“Edge AI 的价值不是把模型搬上板子，而是让诊断闭环留在现场。我们已经证明精度、体积和跨负载边界，下一步用真实板端时间和功耗把工程证据补齐。”

## 评委高频追问

- 为什么准确率高？答：除了模型能力，还因为使用结构化频域特征；更重要的是按原始记录分组切分，避免窗口泄漏。
- 2,504 B 是否包含全部系统？答：不是，只是 INT8 模型参数；固件、RTOS、界面和缓冲区另计。
- 是否已经使用 Ethos-U55？答：当前后端是 Reference C，U55 是后续加速方向，不把未来工作说成已完成结果。
- 97% 是否代表所有工况？答：不代表。LOLO 显示 4 Nm 留出负载为 77.88%，说明真实分布偏移仍需处理。
- 板端时延和功耗是多少？答：当前尚无正式测量结果，比赛中应明确列为下一阶段实机基准，不估算、不编造。
