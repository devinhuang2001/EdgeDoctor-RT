## 2 · 行业痛点：三个断点

**念这句：**「传统巡检的三个断点。」

**画面顶部有一句总判断，先念出来：**「巡检依赖经验、判定依赖阈值、追溯依赖台账——三者之间没有闭环。」

**口述要点**
1. 先给判断：「**设备不会突然坏掉**。真正的问题是，它变坏的过程，今天的方法既看不见，也留不下来。」
2. **看不见**——靠人耳听、手心摸，异常藏在整机噪声里，凭经验下结论，**事后无从复现**。（可压缩）
3. **算不准**——固定阈值一刀切，工况一换，正常振动被误判成故障；同一条曲线，换个班组换个结论。
4. **留不住**——报警只留下一条提示，故障前后的波形、频谱、工况没有留存，**复盘无据可查**。
5. 落到画面底部那行大字收口：「**断点不在采集，而在采集之后。**」

**画面指引**：念到"看不见 / 算不准 / 留不住"时，手指依次压在 01 / 02 / 03 三个编号上。

**过渡**：「所以我们把它做成了一台边缘盒子。」

## 附：可能被问到的问题与回答要点

**Q1 和市面上的振动监测产品有什么区别？**
差别在**结论在哪产生**。多数方案把原始振动传上云再分析，我们**在 M55 应用核本地完成特征提取与五分类推理**，原始波形不出设备；出设备的是结论、置信度与可回放证据。

**Q2 五分类是哪五类？准确率多少？**
正常、轴承内圈、轴承外圈、不对中、不平衡。当前演示工况下**轴承内圈类识别置信度 96.5%**；完整分类准确率仍在扩充工况样本后复测。

**Q3 208 Hz 为什么够？转频只有 42.3 Hz。**
208 Hz 对 42.3 Hz 转频约 **4.9 倍过采样**，能稳定覆盖到 **3× 及以上转频倍频**（42.3 / 86.1 / 124.7 Hz 三个峰都能清晰分辨），满足轴承与不对中的主峰定位需求。更高频段（如轴承高频共振）属于后续扩展方向。

**Q4 断网了怎么办？会不会漏掉事件？**
不会。事件日志与前后证据片段**持久化在本地 Flash**，断网期间照常检测、照常记录；恢复连接后通过 **MQTT 增量同步**补齐，历史事件可离线回放复现同一结论。

**Q5 误报怎么控制？**
**运行基线按设备、安装位置与工况分版本自动匹配**，替代固定阈值一刀切——这是降低误报的主要手段。同时**低质量数据在采集层就被拦下，不进入推理**（数据有效率 99.2%）。

**Q6 为什么选 PSOC Edge E84 / RT-Thread？**
E84 提供 **M33 安全核 + M33 非安全核 + M55 应用核**的异构结构，安全与非安全任务可隔离，M55 专门承担 DSP 与推理负载；RT-Thread 实时性满足 **208 Hz 连续采样不丢帧**的时序要求。

**Q7 现在到什么阶段了？**
已完成**端到端可运行原型**：设备端 LVGL 六标签页、板载五分类推理、事件证据链、MQTT 同步，以及移动端 H5 与 PC 大屏前端均已跑通，并在**六分区数字孪生工厂**场景下完成多区域验证。下一步是真实产线长周期标定。

**Q8 为什么把 96.8% / 99.2% / 3 秒 放在价值页？**
因为它们分别回答三个不同的问题：**96.8%** 回答"现在设备好不好"，**99.2%** 回答"数据信不信得过"，**3 秒** 回答"出事来不来得及"——三个数合起来才是完整价值主张。
